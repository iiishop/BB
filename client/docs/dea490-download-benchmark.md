# DEA-490 更新包并发测速

2026-11-22 UTC，Linux x86_64，Flutter 3.47.9，Dart 3.13.7。同一台机器、同一网络、同一资产 `bb-0.2.3-windows-x64.zip`，Release v0.2.3，资产 ID `778241747`，32,222,014 字节。[GitHub Release](https://github.com/iiishop/BB/releases/tag/v0.2.3)

本机匿名 GitHub REST 资产入口返回 HTTP 403 和 `X-RateLimit-Remaining: 0`。测速用测试传输将安装包及清单的两个冻结资产 URL 映射到同一 Release 的公开下载地址。每轮由实际客户端跟随 GitHub 的 HTTPS CDN 跳转、传输和落盘，再对照同一份发布清单做 SHA-256 校验。计时覆盖安装包请求至校验完成，清单每组取一次。每轮新建 HTTP 客户端和暂存文件。峰值统计尚未读完响应体的请求，不计入已结束的探测请求。生产匿名 REST 入口和目标设备用时仍待独立验证。

```bash
cd client
BB_BENCH_PUBLIC_RELEASE=1 flutter test --no-pub --reporter expanded test/release_download_benchmark.dart
```

每组按 `1, 8, 8, 1, 1, 8, 8, 1` 交替。两组共 16 次通过 SHA-256 校验，下载失败 0 次，回退 0 次。

8 路在第一组慢 30 ms，在第二组快 72.5 ms，合计中位数快约 1.8%。两组收益方向不同，因此 Windows 和 Android 默认使用单路。可在客户端构建时设置 `--dart-define=BB_UPDATE_DOWNLOAD_CONCURRENCY=8` 复验或启用。配置范围为 1–8，每段至少 2 MiB，至少能拆成两段才会探测。分段要求最终端点返回有效的 206、完整长度和强 ETag。回退从零开始读完整包，仍需通过清单校验。
