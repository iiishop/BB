## BB 0.0.3

本版修好 Windows 上用 Ctrl+V 粘贴文件必然失败的问题，并给头像加上从系统相册（Android）或文件管理器（桌面）选图的入口。仍是早期自托管客户端；下载包不包含服务端。

### 修复

- **Windows 粘贴任意文件都报 `missing extension byte`**：中文 Windows 上，PowerShell 即使以 0 退出，也会向 stderr 写一段本地化的进度记录（CLIXML）。旧代码用严格 UTF-8 解码这段输出，在检查退出码之前就抛 `FormatException`，于是 PNG、JPG、PDF 和文件夹全部走同一条失败路径。现在按原始字节读取并忽略成功运行时的进度噪声，只把真正的失败当作失败。文件夹仍然明确提示不支持，行为未变。
- 选图过程中，先前一次解码的迟到结果不会再覆盖你后来手输的路径。

### 新增

- **更换头像入口**：Android 点按选图走系统相册；桌面端在路径输入框旁新增按钮，直接打开系统文件管理器，手填路径的方式保留。

### 从旧版本升级

- 0.0.2 及以上的 Windows / Android 安装可以在应用内检查到本版并升级；0.0.1 仍需手动安装一次。
- Android 请选与现有安装相同 ABI 的 APK。展示版本 `0.0.3`，基础构建号由 `3` 增至 `4`，签名密钥与 applicationId 不变。异签名、跨 ABI 或已有更高 versionCode 的安装不保证可覆盖，**不要为了安装而卸载并丢失数据**。
- Windows 沿用完整载荷替换与失败恢复：不要在应用运行时直接覆盖安装目录；旧目录先保留，直到新版本确认可用。
- Linux 和 macOS 本版仍为手动下载更新，没有应用内安装。

### 已知边界

- Android 相册选图与 Windows 文件选择对话框的系统原生窗口仍需人工验收。自动化覆盖的是解码、路径归属、布局与提交契约，不等于原生对话框已在所有设备上验证。
- Android APK/AAB 继续使用仓库公开的 **debug keystore**；Windows 无 Authenticode 签名，macOS 无 Developer ID 签名与公证。系统可能提示风险或阻止运行，不作为应用商店正式分发包。

### 下载与校验

Windows ZIP 继续自带最小 FFmpeg 8.1.3 与 zlib 1.3.1，不依赖系统 PATH 中的 FFmpeg；源码信息、构建脚本与许可保留在包内 `ffmpeg/`。下载后可用随 Release 提供的 `SHA256SUMS` 检查完整性；校验和不等于独立数字签名。

### 开发与构建

- Windows 测试包继续按实际相关路径裁剪触发，并复用按源码、构建参数、工具链与 ref 隔离的 FFmpeg 依赖缓存；最终包校验与无系统 FFmpeg 冒烟保留。正式 Release 独立从固定源码构建依赖。
- 修复 Windows 测试包里 FFmpeg 依赖校验与应用载荷校验混在一起的顺序错误：依赖校验在应用构建前执行，不应要求 `bb_updater.exe` / `bb-build.json`；应用载荷要求保留在最终 bundle 校验中。
