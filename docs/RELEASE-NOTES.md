## BB 0.0.2

本版为 Windows 和 Android 加入客户端更新入口，并加强更新时的草稿、发送任务与安装文件保护。仍是早期自托管客户端；下载包不包含服务端。

### 新增

- **检查新版本**：Windows 和 Android 每次启动在后台检查正式 Release，不阻塞登录和聊天；设置页也可手动检查。更新说明直接展示 Release 原文，只提示更高版本，不自动下载或退出应用。
- **下载与安装**：由你点击下载，查看进度，取消或失败后重试。下载校验通过后再点击安装；缺少对应架构文件、下载不完整或校验和不一致时拒绝安装。
- **Windows 更新与恢复**：独立更新程序等待旧进程退出后替换完整载荷，包括 FFmpeg、DLL、资源和许可证。新应用启动确认失败时尝试恢复旧目录，保留备份与不属于应用载荷的用户文件。
- **Android 安装入口**：下载对应 CPU 架构的 APK，通过系统安装界面确认；需要时引导开启“允许此来源安装”。同包名、同签名且版本码递增才允许继续，不静默安装、不卸载旧应用。

### 数据保护与修复

- 有未处理草稿、待发送附件、失败后可重试内容、媒体准备或发送/上传任务时，阻止开始安装，并说明需要处理的项目。离开聊天页面不会被当成主动丢弃草稿。
- 更新检查、下载和安装失败可见；恢复和清理未结束前不接受新的安装重试，避免多个更新事务互相覆盖。
- Android 安装校验显式读取签名信息，并兼容 Android 7/8 的版本码接口；拒绝签名不符、同版本和降级安装。

### 从旧版本升级

- **0.0.1 尚无这套更新入口，需要手动下载并安装 0.0.2 一次**。Windows 请先退出旧程序，将完整 ZIP 解压到新目录运行，勿直接覆盖正在使用的目录；旧目录先保留。没有载荷清单的历史 Windows 安装不支持本版更新执行器就地接管。
- Android 请选与现有安装相同 ABI 的 APK；大多数 64 位手机使用 `arm64-v8a`，不要安装 AAB。展示版本为 `0.0.2`，基础构建号从 `2` 增至 `3`，签名密钥与 applicationId 不变；分 ABI APK 的实际 versionCode 包含 ABI 偏移。异签名、跨 ABI 或已有更高 versionCode 的安装不保证可覆盖，**不要为了安装而卸载并丢失数据**。
- 旧开发版本 `0.2.0` 高于 `0.0.2`，不会被当成可自动升级的低版本；Linux 包管理器也可能视其为降级。
- Linux 和 macOS 本版仍手动下载更新，没有应用内安装功能。操作前建议备份账号配置与聊天数据。

### 已知边界

- 自动化覆盖了 Windows 原生更新/失败恢复、真实打包应用启动确认，以及 Android 安装逻辑契约；**Android 真机安装、来源权限与安装后进程替换，用户 Windows 桌面人工操作仍未完成验收**。自动化通过不等于所有设备都已验证。
- Windows 更新采用两次目录重命名，不是整体原子切换。恰逢断电可能需要保留相邻事务目录并运行其中的 `Recover BB.exe` 恢复旧安装；不要自行删除该目录。
- Windows 中文输入法、系统剪贴板及不同桌面上的视频交互仍有待人工验证。公开 GitHub Release 无凭据请求的成功路径此前受限流影响，尚无客户端端到端在线升级实测。
- Android APK/AAB 仍使用仓库公开的 **debug keystore**，不是生产签名；Windows 无 Authenticode 签名，macOS 无 Developer ID 签名/公证。系统可能提示风险或阻止运行，不作为应用商店正式分发包。

### 下载与校验

Windows ZIP 继续自带最小 FFmpeg 8.1.3 与 zlib 1.3.1，不依赖系统 PATH 中的 FFmpeg；源码信息、构建脚本和许可保留在包内 `ffmpeg/`。下载后可用随 Release 提供的 `SHA256SUMS` 检查文件完整性；校验和不等于独立数字签名。

### 开发与构建

- Windows PR 测试包只在实际相关路径变化时构建，并复用按源码、构建参数、工具链和 ref 隔离的 FFmpeg 缓存；最终包校验与冒烟保留。正式 Release 仍独立从固定源码构建依赖。
- QA 证据工具新增原生 Node、pytest 与 Flutter 报告解析，严格区分目标断言失败、运行时/编译错误及跳过或截断的报告。
