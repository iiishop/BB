## BB 0.1.1

本版修好 Android 上应用内更新装不上的问题。BB 空间的功能与 0.1.0 相同。

### 修复

- **Android 更新安装被误拒**：下载和 SHA 校验都通过后，点安装提示「安装包不在应用私有目录，已拒绝安装」。根因是路径检查要求「规范化路径必须与字面路径完全相同」，而 Android 会用 `/data/data` 和 `/data/user/0` 两个名字指向同一份私有存储，平台交给应用的路径是别名那一侧，一规范化就不等了，于是合法路径被判成越界。现在只检查规范化后是否落在私有目录之内；真正指向外部的符号链接解析到目录外，仍然会被拒绝。
- 把「安装包不在私有目录」和「系统拒绝共享路径」两种失败分开显示。之前共用一句话，出问题时看不出是路径检查还是 FileProvider 配置。

### BB 空间（0.1.0 起）

说说流、草稿、任意深度回复、转发链、删除语义、已读与浏览分离、通知路由，手机 / PC / 折叠屏三形态布局；DSH 插件里有对应的空间工具。

### 从旧版本升级

- **这一版必须手动安装一次**。0.0.2 和 0.1.0 的应用内更新都带着上面那个缺陷，会在安装环节被拦下。请从下载页手动取 `bb-0.1.1-android-arm64-v8a.apk`（其他架构同理）安装，之后的应用内更新恢复正常。
- Android 展示版本 `0.1.1`，基础构建号 `6`，签名密钥与 applicationId 不变。不要为了安装而卸载并丢失数据。
- Windows 沿用完整载荷替换与失败恢复；不要在应用运行时直接覆盖安装目录。
- 服务端需要同步升级才能提供空间接口。旧服务端不会让聊天失败，只在空间入口提示能力不可用。

### 已知边界

- 这次修复由 JVM 契约测试复现，**没有在报障设备上实测**。如果升级后仍提示「安装包不在应用私有目录」，说明还有别的入口；如果改提示「系统拒绝了安装包的共享路径」，问题在 FileProvider 的路径配置，两句话现在能分开了。
- 空间这一版仍未在真机验收：Android 相册选图、Windows 文件对话框、折叠屏真机、真实模型识图与工具组合都没有跑过。
- 第一版不含：推荐算法、关注/好友流、可见范围设置、视频说说、评论图片、已发布内容编辑、空间装修、agent 自动刷流。

### 下载与校验

Windows ZIP 继续自带最小 FFmpeg 8.1.3 与 zlib 1.3.1。下载后可用随 Release 提供的 `SHA256SUMS` 检查完整性；校验和不等于独立数字签名。
