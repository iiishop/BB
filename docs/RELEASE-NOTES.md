## BB 0.1.5

这一版都在「打开会话更快」这条线上，另有服务端两处底层调整。

### 打开会话变快

- **头像不再下载原图**。以前头像存的是上传分辨率，实测两个文件 711 KB 和 541 KB，加起来 1.25 MB —— 冷启动、清缓存、换设备时要实打实下完。现在服务端在上传时多存一份 512 px 的缩略图，列表、聊天气泡、空间头像、侧栏都用它，**两张合计降到 56 KB**（23 倍和 22 倍）。资料页仍用原图，那里要看清楚。
- **同一张图片不再反复请求**。之前图片的加载 future 建在 `build` 里，任何一次界面刷新（在线状态变化、3 秒轮询、头像到达）都会让所有可见图片重新请求一遍。消息里带图多的时候，打开会话看起来像在把图片全部载入一次。现在每个 media 只请求一次。
- **首屏不再等本地记账**。打开会话时有一段纯本地的操作记录核对（每条自己发的消息一次读、常常还有一次写，串行），它挡在消息渲染前面。现在挪到后台，失败不影响已经渲染的内容。

### 服务端

- **头像缩略图**：上传时额外生成一份，`GET /avatars/{account}.png?variant=thumb` 取派生图。老头像没有派生图时自动回退原图。
- **数据库锁等待交给 SQLite**：原来是自己写重试循环（每次撞锁抛异常回 Python、退避、重跑语句），现在用 SQLite 的 `busy_timeout`，等待发生在 C 层。日常日志里那两类锁噪音（`storage_lock_retry` / `recovered`）不再出现；真出现 `storage_lock_exhausted` 才是需要查慢事务的信号。

### 从旧版本升级

- Android 展示版本 `0.1.5`，基础构建号 `10`，签名密钥与 applicationId 不变。0.1.1 及以后可以直接应用内更新。
- Windows 沿用完整载荷替换与失败恢复；不要在应用运行时直接覆盖安装目录。
- **服务端需要同步升级**才能提供头像缩略图接口。旧服务端不会让客户端出错：请求派生图拿不到就回退原图，只是省不下那 1.25 MB。

### 已知边界

- 打开会话的真机手感仍未在长会话上验过：库里只有两百多条消息，窗口加载和全量加载看不出差别。
- 已存在的头像不会自动生成缩略图（只有新上传会写），需要补的话要跑一次离线迁移。
- 空间仍未在真机验收：Android 相册选图、Windows 文件对话框、折叠屏真机、真实模型识图与工具组合都没有跑过。
- 第一版不含：推荐算法、关注/好友流、可见范围设置、视频说说、评论图片、已发布内容编辑、空间装修、agent 自动刷流。

### 打包

Windows ZIP 自带最小 FFmpeg 8.1.3 与 zlib 1.3.1。测试包与正式发布使用同一份固定校验的依赖产物，发布前校验归档哈希、目录树 digest 与构建脚本一致性。下载后可用随 Release 提供的 `SHA256SUMS` 检查完整性；校验和不等于独立数字签名。
